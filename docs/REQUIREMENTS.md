## 概要

GitHub Issues をデータソースとして、Backlog 風のプロジェクト管理 UI（課題一覧・ボード・ガントチャート）を提供する Web アプリケーション。

| 項目 | 内容 |
|------|------|
| アプリ名 | IssueBoard |
| フレームワーク | React 19 + Vite 8 |
| スタイリング | Tailwind CSS 4 + @tailwindcss/typography |
| Markdown | react-markdown + remark-gfm |
| 外部ライブラリ追加 | なし（ガントチャート・D&D は自前実装） |
| 対応環境 | PC ブラウザ（レスポンシブ非対応） |
| 言語 | 日本語 |

---

## 1. 認証

| 項目 | 仕様 |
|------|------|
| 認証方式 | GitHub Personal Access Token（PAT） |
| 必要スコープ | `repo`（Issues の読み書き） |
| トークン保存先 | ブラウザの `localStorage`（キー: `github_token`） |
| 接続先リポジトリ | `.env` の `VITE_REPO_OWNER` / `VITE_REPO_NAME` で指定 |
| トークン検証 | `GET /user` で有効性チェック後にログイン許可 |
| ログアウト | `localStorage` からトークンを削除し、状態をリセット |

## 2. データモデル

### 2.1 ラベル分類

GitHub リポジトリのラベルを **description（説明）フィールド** の内容で自動分類する。

| description に含む文字列 | 分類 | 用途 |
|--------------------------|------|------|
| `priority` または `priority:N` | 優先度ラベル | 課題の優先度を表す |
| `category` | カテゴリラベル | 課題の分野・部門を表す |
| `status` または `status:N` | ステータスラベル | 課題の進捗状態を表す |

- 各分類は排他ではない（1 つの Issue に優先度・カテゴリ・ステータスを各 1 つ付与可能）
- 上記いずれにも該当しないラベルは分類対象外（ボードのカードでは色付きバッジとして表示）
- `priority:N` / `status:N` の `N` は表示順序（数値が小さいほど先頭）。省略時は末尾に配置

#### ラベル設定例

| ラベル名 | Description | 分類 |
|----------|-------------|------|
| 🔴 緊急 | `priority:1` | 優先度（1番目） |
| 🟡 今週 | `priority:2` | 優先度（2番目） |
| 🔵 次週以降 | `priority:3` | 優先度（3番目） |
| 👀 確認待ち | `priority:4` | 優先度（4番目） |
| 🏢 経理総務 | `category` | カテゴリ |
| 👥 採用労務 | `category` | カテゴリ |
| 🔒 情シス | `category` | カテゴリ |
| 💼 人事制度 | `category` | カテゴリ |
| 🌐 コーポレート | `category` | カテゴリ |
| 未対応 | `status:1` | ステータス（1番目） |
| 処理中 | `status:2` | ステータス（2番目） |
| 処理済み | `status:3` | ステータス（3番目） |

#### ボードの列順序

ステータス別ボードの列は左から以下の順で表示される:

1. **未設定**（ステータスラベルなしの Issue、該当 Issue がある場合のみ表示）
2. **ステータスラベル**（デフォルトは `status:N` の N 昇順。N 未指定時は GitHub API の返却順を維持）

#### 列の並び替え

| 項目 | 仕様 |
|------|------|
| 操作方法 | 列ヘッダーをドラッグ&ドロップで並び替え |
| ドラッグハンドル | 列ヘッダー左端の `⠿` アイコン |
| 対象外 | 「未設定」列は並び替え不可（常に先頭固定） |
| 永続化 | 並び順は `localStorage` に保存され、次回アクセス時に復元される |
| 保存キー | ステータス順: `issueboard_status_order`、優先度順: `issueboard_priority_order` |

### 2.2 期限

- Issue 本文に `📅 期限: YYYY-MM-DD` または `📅 期限: YYYY/MM/DD` の形式で記載
- 正規表現: `/📅\s*期限[:：]\s*(\d{4}[-/]\d{1,2}[-/]\d{1,2})/`
- 表示ルール:

| 条件 | 表示 | スタイル |
|------|------|---------|
| 期限超過 | `🔥 M/D（X日超過）` | 赤・太字 |
| 3 日以内 | `⚠️ M/D（あとX日）` | オレンジ・中太字 |
| それ以外 | `📅 M/D` | グレー・通常 |

### 2.3 担当者（Assignee）

- GitHub Issues の `assignee` フィールドを利用
- アバター画像 + ユーザー名で表示
- 未設定の場合は `-` または「未設定」と表示

## 4. 課題ビュー（IssueTable）

### 4.1 フィルターバー

| フィルター | 仕様 |
|-----------|------|
| キーワード検索 | タイトルまたは Issue 番号で部分一致検索（幅 208px） |
| 優先度フィルター | ドロップダウン、「全ての優先度」+ 各優先度ラベル |
| ステータスフィルター | ドロップダウン、「全てのステータス」+ 各ステータスラベル（ステータスラベルが 0 件の場合は非表示） |
| 担当者フィルター | ドロップダウン、「全ての担当者」+「未設定」+ Issue に存在する担当者一覧 |
| 親タスクのみ | チェックボックス。ON にするとサブタスクを持つ親 Issue のみ表示。フィルター適用時はツリーをフラット表示にフォールバック |
| カテゴリフィルター | ドロップダウン、「全てのカテゴリ」+ 各カテゴリラベル |
| 件数表示 | フィルター後の件数を右端に表示 |

### 4.2 テーブル

| 列 | 幅 | ソート | 内容 |
|----|-----|--------|------|
| # | 64px | Issue番号 | `#123` 形式 |
| 件名 | 可変 | タイトル（ja ロケール） | 優先度ドット + タイトル |
| 担当者 | 96px | login 名 | アバター(20px) + ユーザー名 |
| 状態 | 112px | ステータス順 | 色付きバッジ（ステータスラベル 0 件時は列非表示） |
| 優先度 | 112px | 優先度順 | ラベル名テキスト |
| カテゴリ | 128px | カテゴリ名（ja ロケール） | 色付き丸バッジ |
| 期限 | 128px | 日付 | 期限表示（色分け付き） |
| 作成日 | 112px | 日付（デフォルト降順） | `YYYY/MM/DD` 形式 |

- 列ヘッダークリックで昇順/降順切替（`↕` / `↑` / `↓` アイコン）
- デフォルトソート: 作成日降順
- 行クリックで右側に課題詳細パネルを表示
- 選択中の行は `bg-blue-50` でハイライト

### 4.3 課題詳細パネル（右サイド）

| 項目 | 仕様 |
|------|------|
| パネル幅 | 420px |
| ヘッダー | `#番号` + タイトル + 閉じるボタン |
| 属性表示 | 担当者、状態、優先度、カテゴリ、期限、作成日 |
| 本文 | Markdown レンダリング（GFM 対応） |
| コメント | 一覧表示（アバター・ユーザー名・日時）+ 追加フォーム |
| 状態変更 | ステータスラベルのボタン群（現在のステータスはハイライト） |
| 優先度変更 | 優先度ラベルのボタン群（現在の優先度はハイライト） |
| 完了操作 | Issue を Close（確認ダイアログあり） |
| GitHub連携 | 「GitHubで開く」リンク（新しいタブ） |

### 5.1 ツールバー

**表示切替**:

| ボタン | 動作 |
|--------|------|
| ステータス別 | ステータスラベルを列として表示（デフォルト） |
| 優先度別 | 優先度ラベルを列として表示 |

**担当者フィルター**:

| 項目 | 仕様 |

### 5.2 カンバンボード

| 項目 | 仕様 |
|------|------|
| 列幅 | 320px（固定、横スクロール対応） |

### 5.3 ドラッグ & ドロップ

| 項目 | 仕様 |
|------|------|
| ドラッグ対象 | 各カード（`draggable` 属性） |

| 更新中表示 | 右下に「更新中...」トースト |
| カーソル | 通常: `cursor-grab`、ドラッグ中: `cursor-grabbing` |

### 5.4 カードクリック → 詳細表示

| 項目 | 仕様 |

## 7. 親子課題

### 7.1 データモデル

親 Issue の本文にタスクリスト形式（`- [ ] #N`）で子 Issue を列挙することで親子関係を表現する。

```markdown
### サブタスク
- [ ] #2
- [ ] #3
- [x] #4
```

- 子 Issue を Close すると、GitHub が自動的に `[x]` に更新する
- 子 Issue 側に特別な記法は不要（通常の Issue として作成するだけ）
- アプリは全 Issue（Open + Closed）の本文を走査して親子関係を自動構築する
- Closed な親 Issue を持つ Open 子 Issue も正しく親子関係が表示される

### 7.2 課題一覧での表示

| 項目 | 仕様 |
|------|------|
| ツリー表示 | 親 Issue の直下に子 Issue をインデント表示（フィルター・検索未適用時のみ） |
| フィルター時 | フィルターまたは検索が適用されている場合はフラット表示にフォールバック（条件に一致する子 Issue が消えない） |
| 展開/折りたたみ | 親 Issue の ▶/▼ ボタンで子の表示を切替 |
| 子のインデント | `└` 記号 + 左パディング 20px |
| 進捗表示 | 親 Issue の件名横に `(完了数/総数)` を表示 |

### 7.3 詳細パネルでの表示

| 項目 | 仕様 |
|------|------|
| 親課題リンク | 子 Issue の場合、属性欄の上に親 Issue へのリンクを表示（クリックで親の詳細に遷移） |
| サブタスク一覧 | 親 Issue の場合、属性欄の下にサブタスクリストを表示 |
| 進捗バー | サブタスクの完了率をプログレスバーで表示 |
| チェック状態 | 各サブタスクの ✓/○ 状態を表示（`[x]` = ✓） |
| サブタスクリンク | 各サブタスクをクリックで詳細に遷移 |

### 7.4 ボードでの表示

| 項目 | 仕様 |
|------|------|
| 進捗バー | 親 Issue のカードにサブタスク進捗バー + `完了数/総数` を表示 |

### 7.5 ガントチャートでの表示

#### ツリー表示（グルーピング「なし」時）

| 項目 | 仕様 |
|------|------|
| ツリー構造 | 親 Issue の直下に子 Issue をインデント表示 |
| 展開/折りたたみ | 親行の ▶/▼ で子行の表示を切替 |
| 子のインデント | `└` 記号 + 左パディング 18px |
| 進捗表示 | 親行のタイトル横に `(完了数/総数)` を表示 |
| 親サマリーバー | 子の最小開始日〜最大期限をカバーする菱形+線のバー（Backlog 風） |
| 子のバー | 通常のバー（角丸） |
| 親行の背景 | 薄いグレー（`bg-gray-50/50`）で視覚的に区別 |

#### グルーピング「親課題」時

| 項目 | 仕様 |
|------|------|
| グループ名 | `#番号 タイトル`（親 Issue 自身と子 Issue が同じグループ） |
| 独立課題 | 親子関係のない Issue は「独立課題」グループに分類 |

### 7.6 新規作成での対応

| 項目 | 仕様 |
|------|------|
| 親課題選択 | ドロップダウンで親 Issue を選択可能（「なし」がデフォルト） |
| 作成時処理 | 子 Issue 作成後、親 Issue の本文に `- [ ] #N` を自動追記（API で PATCH） |
| 紐付け失敗時 | 子 Issue は作成済みとして一覧を再取得し、紐付け失敗のみアラートで通知。手動で親の本文にタスクリストを追加するよう案内 |
| 候補 | 他の Issue の子でない Issue のみ候補に表示 |

## 8. バーンダウンチャート（BurndownChart）

GitHub Milestone に紐づく Issue の残課題数を時系列で可視化する。

### 8.1 前提条件

- GitHub リポジトリに Milestone が作成されていること
- Milestone に Issue が紐づけられていること
- Issue の Close が「完了」を意味する

### 8.2 ツールバー

| 項目 | 仕様 |
|------|------|
| マイルストーン選択 | ドロップダウン。全 Milestone（Open + Closed）を表示。初期値は `due_on` がある最新の Milestone |
| サマリー | 総課題数、完了数（緑）、残数（青）を表示 |

### 8.3 チャート

| 項目 | 仕様 |
|------|------|
| 横軸 | 日付（開始日〜終了日） |
| 縦軸 | 残課題数（0〜総課題数） |
| 開始日 | Milestone description に `開始日: YYYY-MM-DD` または `開始日: YYYY/MM/DD` があればそれを優先。未指定時は Milestone 内最古の Issue 作成日 |
| 終了日 | Milestone の `due_on`（なければ今日 + 14 日） |
| 表示範囲 | 開始日〜MAX(終了日, 今日) |
| 理想線 | 開始時の課題数から 0 まで直線（グレー破線） |
| 実績線 | 日ごとの残課題数を折れ線で表示（青実線）。過去の日のみ描画 |
| 今日の線 | 赤い破線で縦に表示 |
| 完了の定義 | Issue が Close された日に残数を -1 |
| 凡例 | 理想線・実績線・今日の線の凡例を左上に表示 |
| 描画方式 | SVG（外部ライブラリ不使用） |

### 8.4 マイルストーン未設定時

マイルストーンが 0 件の場合、「マイルストーンが設定されていません」メッセージと GitHub での作成案内を表示。

## 9. 設定画面（SettingsView）

サイドバーの「設定」メニューからアクセスする管理画面。

### 9.1 タブ構成

| タブ | 管理対象 | 対応する GitHub リソース |
|------|---------|----------------------|
| ステータス | ステータスラベル | Label（description に `status` を含む） |
| 優先度 | 優先度ラベル | Label（description に `priority` を含む） |
| カテゴリ | カテゴリラベル | Label（description に `category` を含む） |
| マイルストーン | マイルストーン | Milestone |

### 9.2 ラベル管理（ステータス・優先度・カテゴリ共通）

| 操作 | 仕様 |
|------|------|
| 一覧表示 | 色ドット + ラベル名 + 順序番号。description の分類に基づいてフィルター表示 |
| 作成 | 色選択 + ラベル名 + 順序番号を入力。description は `keyword:N` 形式で自動生成 |
| 編集 | 一覧の「編集」ボタンでインライン編集フォームを表示 |
| 削除 | 確認ダイアログ後に削除。該当ラベルが付与された Issue からも自動除去される |

### 9.3 マイルストーン管理

| 操作 | 仕様 |
|------|------|
| 一覧表示 | 状態バッジ（Open/Closed）+ タイトル + 期限日 + 説明 |
| 作成 | タイトル + 期限日 + 説明を入力 |
| 編集 | 一覧の「編集」ボタンでインライン編集フォームを表示 |
| Close/Reopen | 状態の切り替え |
| 削除 | 確認ダイアログ後に削除。紐づく Issue のマイルストーンが解除される |

### 9.4 データ連携

設定画面で変更を行うと、`onDataChanged` コールバックで App.jsx の `loadData` が呼ばれ、課題一覧・ボード等の表示が最新化される。

## 11. GitHub API 利用

| 操作 | エンドポイント | メソッド | ページネーション |
|------|---------------|---------|----------------|
| Issue 一覧取得（Open） | `/repos/{owner}/{repo}/issues?state=open` | GET | 100件/ページ、全件取得 |
| Issue 一覧取得（全件） | `/repos/{owner}/{repo}/issues?state=all` | GET | 100件/ページ、全件取得。親子関係構築用 |
| ラベル一覧取得 | `/repos/{owner}/{repo}/labels` | GET | 100件/ページ、全件取得 |
| コメント取得 | `/repos/{owner}/{repo}/issues/{number}/comments` | GET | 100件/ページ |
| コメント追加 | `/repos/{owner}/{repo}/issues/{number}/comments` | POST | - |
| Issue Close | `/repos/{owner}/{repo}/issues/{number}` | PATCH | - |
| ラベル設定 | `/repos/{owner}/{repo}/issues/{number}/labels` | PUT | - |
| Issue 作成 | `/repos/{owner}/{repo}/issues` | POST | - |
| Issue 本文更新 | `/repos/{owner}/{repo}/issues/{number}` | PATCH | - |
| Milestone 一覧取得 | `/repos/{owner}/{repo}/milestones?state=all` | GET | 100件/ページ、全件取得 |
| Milestone Issue 取得 | `/repos/{owner}/{repo}/issues?milestone={number}&state=all` | GET | 100件/ページ、全件取得。PR 除外 |
| ラベル作成 | `/repos/{owner}/{repo}/labels` | POST | - |
| ラベル更新 | `/repos/{owner}/{repo}/labels/{name}` | PATCH | - |
| ラベル削除 | `/repos/{owner}/{repo}/labels/{name}` | DELETE | - |
| Milestone 作成 | `/repos/{owner}/{repo}/milestones` | POST | - |
| Milestone 更新 | `/repos/{owner}/{repo}/milestones/{number}` | PATCH | - |
| Milestone 削除 | `/repos/{owner}/{repo}/milestones/{number}` | DELETE | - |
| トークン検証 | `/user` | GET | - |

- 全リクエストに `Authorization: token {PAT}` ヘッダーを付与
- `Accept: application/vnd.github.v3+json`
- Issue 一覧取得時、Pull Request は `pull_request` フィールドの有無で除外
- ラベル設定（PUT）は既存ラベルを全置換する仕様
